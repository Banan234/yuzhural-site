# Поиск в каталоге

Поиск выбирает реальные позиции каталога по названию, артикулу и проверяемым параметрам. Выдача и подсказки используют один движок: `shared/catalogSearch.js`.

## Как определяется запрос

1. Нормализуются регистр, `ё`, пробелы, дефисы, десятичная запятая и знаки умножения. `3х2,5`, `3x2.5`, `3 × 2,50`, `3*2.5` и `3 на 2.5` задают одинаковый размер.
2. Точный артикул имеет высший приоритет. Поддерживаются `YU-0000107`, `yu0000107`, `артикул YU-0000107`, `код: YU-0000107`. Если артикул полностью цифровой, точное совпадение с ним также имеет приоритет. Добавление `мм²` явно задаёт сечение.
3. Точное название из каталога, включая исходное название поставщика, поднимается первым. Это сохраняет поиск импортных и специальных обозначений с числовыми полями, назначение которых не описано в данных. Цифры в таком названии не получают выдуманного технического смысла.
4. Из остальных запросов извлекаются размеры, сечение, число жил, пары, AWG, напряжение, материал, исполнение, цвет и условие наличия. Все заданные условия применяются одновременно.
5. Остальные слова должны присутствовать в названии, марке, артикуле, производителе, бренде или названии категории/подкатегории. Порядок слов свободный. Поясняющие слова `купить`, `цена`, `нужен`, `ищу` не мешают поиску.
6. Точные обозначения стоят перед совпадениями по началу марки. Явная сортировка каталога по цене или популярности применяется после поиска.

## Числа и размеры

| Запрос                                  | Правило                                                    |
| --------------------------------------- | ---------------------------------------------------------- |
| `185`, `185 мм²`                        | Точное основное сечение 185 по полю `crossSection`         |
| `ВВГ 185`, `185 ВВГ`, `ВВГ185`          | Марка и точное сечение, независимо от числа жил            |
| `ВВГ 3х2.5`                             | Точная размерная конфигурация; не 5х2.5 и не 3х25          |
| `ВВГ 3 2.5`                             | После известной марки два отдельных числа читаются как N×S |
| `ВВГ 3 жилы 2.5`, `трехжильный ВВГ 2.5` | Общее число жил и основное сечение                         |
| `КПС 1х2х0.5`                           | Сохраняются все три числа; не смешивается с 2х0.5          |
| `СИП-2 3х50+1х54.6`                     | Сохраняются число, порядок и размеры дополнительных групп  |
| `СИП 4`, `ПВ 3`, `СКАБ 660`             | Число внутри известной марки остаётся частью марки         |
| `ВВГ 660 В`, `ВВГ 0.66 кВ`              | Одинаковое напряжение; поле каталога хранится в кВ         |
| `F/UTP 4х2хAWG24`, `F/UTP 24 AWG`       | AWG обрабатывается отдельно от мм²                         |
| `UTP cat5e 4 пары`, `UTP кат.5е пар 4`  | Категория и число пар; не сечение 4                        |

Набор `3х50+1х25` не выдаётся как обычный `3х50`. Условие «4 жилы» учитывает группировку и дополнительные жилы по данным каталога. Поиск по одному сечению относится к основным жилам; сечение экрана или дополнительной жилы не подмешивается.

## Марки, исполнения и текст

- Поиск `ВВГ` не включает `АВВГ` и `КВВГ` из-за простого вхождения подстроки. Модификации, начинающиеся с ВВГ, остаются доступными.
- Для короткого фрагмента из двух букв, например `вг`, допускается поиск внутри слова, только когда совпадений по началу нет и сам фрагмент не является известной маркой. Числовые ограничения при этом сохраняются.
- `LS`, `FRLS`, `HF`, `FRHF`, `LTx`, `нг` проверяются отдельно. `LS` не заменяется на `FRLS`. Явно указанная группа `нг(А)` требует эту группу.
- Латинская транслитерация привязывается к существующим маркам: `vvg`, `pugv`, `sip-4`, `vvgng(a)-ls`. Алиасы не создают новых товаров и не означают техническую взаимозаменяемость марок.
- Смешанные визуально похожие буквы в русской марке нормализуются: `BBГ` ищет ВВГ. `NYM` и смешанное `NYМ` обрабатываются одинаково.
- Цвета допускают сокращения и распространённые формы: `бел`, `белого`, `белый`; `черн`, `черный`; `Ж/З`, `желто-зеленый`. Синий и голубой остаются разными цветами.
- Материал определяется общим классификатором каталога. Отсутствующее свойство не угадывается из запроса.
- `F/UTP` и `U/UTP` различаются при явном указании. Обозначения `cat.5e`, `cat5e`, `кат.5е` нормализуются одинаково.
- `в наличии` ограничивает выдачу позициями с положительным остатком.

## Опечатки и пустая выдача

Опечатки не приводят к молчаливой замене запрошенной марки. Если совпадений нет, поиск предлагает отдельные действия «Возможно, вы искали»:

- переключение раскладки: `ddu 3x2.5` → `ввг 3x2.5`;
- одно добавление, удаление, замена или перестановка букв в существующей марке длиной от четырёх символов;
- каждое предложение предварительно проверяется на реальные результаты с исходными размерами и остальными условиями;
- цифры не исправляются; существующая марка не меняется на похожую;
- неоднозначные исправления показываются отдельными вариантами, а выбор делает покупатель.

Пустой ввод открывает каталог. Пунктуация без слов, неизвестные слова, неверный размер и противоречащие друг другу условия дают пустую выдачу. Запрос длиннее 256 символов не выполняется.

## Подсказки и фильтры

Подсказки группируют реальные совпадения по марке и показывают их количество. Выбор сохраняет исходный запрос целиком, включая размер, цвет и исполнение, а затем добавляет выбранную марку. Счётчик подсказки соответствует такой выдаче.

Новый поиск из шапки начинается по всему каталогу. Старые цена, марка, категория, сечение, жилы и номер страницы сбрасываются. Сортировка и размер страницы сохраняются. При открытии ссылки с фильтрами они применяются явно; если именно они скрыли результаты, появляется ссылка «Показать без фильтров».

Старые ответы сервера не заменяют подсказки нового запроса. Доступны стрелки, Enter для выбранной подсказки и Escape для закрытия. Обычный Enter сохраняет введённый запрос.

## Проверка

- `shared/catalogSearch.test.js` — технические параметры, текстовые формы, отрицательные примеры, исправления и совпадение подсказок с выдачей.
- `lib/catalogQuery.test.js` — серверный контракт, кэш, фильтры и сортировка.
- `server.test.js` — HTTP API поиска, подсказок и пояснений.
- `HeaderSearch.render.test.jsx` — старые фильтры, клавиатура, выбор подсказок и гонка ответов.
- `CatalogPage.render.test.jsx` — исправления и восстановление выдачи без фильтров.
- `node scripts/auditCatalogSearch.js outputs/catalog-search-audit.json` — каждый товар текущего каталога по названию и артикулу, все основные сечения, примеры покупательских запросов и время обработки.

Индекс хранится по массиву текущего каталога, документы переиспользуются по объекту товара, кэш запросов ограничен 100 записями. После загрузки нового массива товаров используется новый индекс.

## Границы точности

Произвольное пожелание вроде «для бани» нельзя надёжно превратить в технический подбор без подтверждённых свойств и уточнений. Поиск использует имеющиеся данные, сохраняет ограничения покупателя и предлагает исправления явно. Неизвестное напряжение, назначение или материал не считаются подтверждёнными. Качество структурированных параметров зависит от импорта; точное исходное название остаётся доступным даже при неполной разметке специального обозначения.
