# Устойчивые проверки интерфейса

Тест проверяет пользовательский результат. Формулировки, пунктуация, пример
в placeholder и сгенерированные ID могут меняться без изменения поведения.

- Ищите элемент по роли и смысловому имени. Для заголовка всей страницы достаточно
  уровня H1, когда тема страницы уже определяется маршрутом и остальными проверками.
- Ошибка поля: `aria-invalid`, непустое видимое сообщение и рабочая связь через
  `aria-describedby`. Для этого есть `expectFieldError` в `src/test` и `e2e/helpers`.
- Отправка: правильный запрос, блокировка повторного запроса, успешное состояние
  либо ошибка с сохранением введённых данных. Не ищите кнопку по тексту «Отправка…»:
  сохраните её до клика или используйте submit-кнопку внутри нужной формы.
- Цена: сохраняйте точную сумму и различайте числовую цену и расчёт по запросу.
  В состоянии запроса нельзя показывать нулевую цену в рублях.
- Проверяйте, что `aria-controls` указывает на нужную панель, а не конкретное
  написание её ID. Разбирайте SSR HTML как DOM вместо проверки соседства тегов.
- Количество повторов контактов и длина рекламного заголовка не являются контрактом.
  Наличие контактов, корректность каждого адреса ссылки и доступное имя — являются.

Точное сравнение сохраняется для данных тестовых примеров, сумм, технических
параметров, артикулов, API-полей, URL, реквизитов и переданных сервером сообщений.
Проверки склонений и форматирования остаются в тестах соответствующих функций.
Не заменяйте значимую проверку одним `toBeInTheDocument`, не добавляйте `skip`
и не обновляйте ожидания только ради зелёного прогона.

Сценарии должны соответствовать действующему интерфейсу. Главная использует форму
с выбором телефона или email. Восстановление старых ручных позиций корзины проверяется
через persisted-данные; этот тест не проверяет удалённую форму ручного ввода.

## Нужен ли отдельный тест

Оставляем тест, если он обнаруживает самостоятельную ошибку: неверный расчёт,
потерю товара или исходных данных при импорте, ошибочный фильтр, некорректный запрос,
потерю введённых данных, недоступный элемент управления или нарушение защиты.
Проверки функции, HTTP API и браузерного действия не считаются дублями только
потому, что относятся к одной возможности: они защищают разные границы.

Удаляем повтор одного сценария при тех же условиях, сравнение двух обёрток одной
функции без независимого ожидаемого результата и проверки написания констант.
Небольшие проверки ссылок или метаданных объединяем с уже существующим сценарием
той же страницы, если для них не требуется другое состояние.
