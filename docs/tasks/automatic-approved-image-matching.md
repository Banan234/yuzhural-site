# Отложенная задача: автоматический подбор изображений

Статус: отложено по указанию пользователя 9 ноября 2026 года. Сейчас не выполнять.

Ниже сохранено исходное задание пользователя.

Задача: автоматический подбор существующих изображений для новых товаров каталога

Проект: yuzhural-site

Когда выполнять: после завершения формирования библиотеки утверждённых изображений кабелей и их привязки к текущему каталогу.

Цель

Реализовать систему, которая при добавлении новых товарных позиций автоматически подбирает максимально подходящее изображение из уже существующей библиотеки APPROVED.

Новые изображения через API генерировать не нужно, если можно использовать существующие.

Система должна работать без ручного участия при каждом обновлении каталога.

1. Алгоритм подбора

При появлении нового SKU:

1. Определить семейство кабеля по маркировке.
2. Определить количество жил.
3. Определить материал токопроводящих жил.
4. Определить конструкцию жил (однопроволочные/многопроволочные).
5. Определить наличие экрана, брони, огнестойких барьеров FRLS и других визуально значимых элементов.
6. Сформировать технический профиль и visualKey.
7. Найти наиболее подходящее изображение в библиотеке APPROVED.

Сечение жил по умолчанию не должно влиять на выбор изображения, если конструкция визуально не отличается.

Использовать уже реализованные правила familyVisualRules, cableTechnicalConstructionRules.json, cableScreenVisualStandard.json и другие действующие стандарты проекта.

Не создавать параллельную систему правил, противоречащую существующему генератору.

2. Уровни соответствия

Реализовать три статуса:

EXACT

Полное совпадение визуальной конструкции.

* Автоматически назначать изображение.
* Не требовать ручного подтверждения.
* Не запускать генерацию.

SIMILAR

Точного изображения нет, но найден максимально близкий вариант.

* Использовать изображение временно.
* Отмечать назначение как приблизительное.
* Сохранять информацию об отличиях.
* Добавлять позицию в отдельный отчёт.
* Не считать изображение технически точным.

При подборе SIMILAR учитывать количество жил, семейство, материал, геометрию и конструктивные особенности.

Не допускать грубых несоответствий: например, не подменять бронированный кабель обычным, экранированный неэкранированным или алюминиевые жилы медными.

NO_MATCH

Подходящего изображения нет.

* Использовать стандартную заглушку.
* Добавлять товар в список позиций без подходящего изображения.
* Отмечать необходимость создания нового эталона.

3. Автоматическое обновление изображений

Когда в библиотеке APPROVED появляется новый утверждённый эталон:

1. Повторно проверить товары со статусами SIMILAR и NO_MATCH.
2. Найти более точные соответствия.
3. Автоматически заменить временные изображения, если найдено соответствие EXACT.
4. Обновить статусы.
5. Сохранить историю изменений.

Не заменять изображения, вручную закреплённые и защищённые от автоматической замены.

4. Отчётность

Создать отдельный отчёт «Автоматический подбор изображений».

В отчёте показывать:

* Общее количество новых товаров.
* Количество товаров с EXACT.
* Количество товаров с SIMILAR.
* Количество товаров с NO_MATCH.
* Количество автоматически назначенных изображений.
* Количество временных изображений.
* Количество заменённых временных изображений.
* Количество позиций, для которых требуется генерация нового эталона.

Предусмотреть подробную таблицу:

SKU	Наименование	Статус	Используемое изображение	Источник изображения	Причина выбора

Добавить фильтрацию по статусам и возможность просмотра товаров на сайте.

Отдельно учитывать статистику каждого обновления каталога и общую статистику.

5. Интеграция с каталогом

Система должна автоматически запускаться после импорта или обновления товарных позиций.

Требования:

* Не создавать дубли изображений.
* Использовать одно изображение для нескольких подходящих SKU.
* Не перезаписывать библиотеку APPROVED.
* Не изменять утверждённые эталоны.
* Не выполнять платные API-запросы для поиска соответствий.
* Не менять существующие корректные назначения без необходимости.
* Сохранять историю автоматических назначений и замен.
* Обеспечить повторяемость результатов при одинаковых входных данных.

6. Приоритет подбора

Использовать следующую последовательность:

1. Точное совпадение visualKey.
2. Совпадение технической и визуальной конструкции с допустимыми различиями в сечении.
3. Наиболее близкая конструкция в пределах безопасных правил совместимости.
4. Заглушка, если подходящего изображения нет.

Не использовать только текстовое сходство маркировок как основание для назначения.

7. Проверка перед внедрением

Перед включением автоматического режима:

1. Провести аудит существующих изображений и назначений.
2. Реализовать dry-run без изменения каталога.
3. Показать статистику предполагаемых назначений.
4. Проверить корректность EXACT, SIMILAR и NO_MATCH на реальных SKU.
5. Проверить повторный импорт каталога.
6. Проверить автоматическую замену SIMILAR на EXACT.
7. Проверить сохранность утверждённых изображений.
8. Добавить автоматические тесты.

Важно: сначала реализовать систему и показать результаты тестового прогона. Не включать автоматическое изменение всего каталога без моего подтверждения.

Ожидаемый результат

После внедрения при каждом обновлении каталога новые товары должны автоматически получать максимально подходящие изображения из существующей библиотеки.

Для точных совпадений участие пользователя не требуется.

Приблизительные назначения должны отдельно учитываться в отчёте, чтобы в будущем можно было постепенно заменять их более точными изображениями.

Основная цель — максимально использовать уже созданные изображения, минимизировать количество новых генераций и постепенно повышать точность визуального оформления всего каталога.
