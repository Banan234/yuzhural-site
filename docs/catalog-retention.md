# Хранение резервных копий и выпусков каталога

## Резервные копии

Перед публикацией импорта создаётся снимок данных. После успешного создания
снимка остаются 14 последних завершённых резервных копий. Число задаётся
`BACKUP_RETENTION` (по умолчанию 14); это количество снимков, а не дней.
Проверка неизменившегося прайса резервную копию не создаёт.

Очистка удаляет только завершённые копии с читаемым manifest.json из BACKUP_DIR
(по умолчанию data/backups). Незавершённые и посторонние каталоги автоматически
не удаляются. Если создание новой копии не завершилось, старые копии не очищаются.

По умолчанию BACKUP_INCLUDE_PUBLIC=false: генерируемая публичная статика
в резервную копию не входит. Перед восстановлением проверить manifest, размеры
и SHA-256 командой npm run backup:verify -- <идентификатор>.

## Выпуски каталога

После успешной транзакции публикации сохраняются три последних выпуска в
`data/.catalog-current-releases` и активный выпуск, если он не входит в эти три.
Ссылка `data/catalog-current` определяет активный выпуск; он никогда не удаляется
этой очисткой. При ошибке публикации действует откат транзакции.

Полные выпуски и резервные копии имеют разное назначение: выпуск содержит
готовый каталог и публичные артефакты, резервная копия — снимок данных перед
обновлением. Удалять один вид хранения вместо другого нельзя.

## Отчёты и локальные материалы

Архивы HTML/JSON-отчётов хранятся 30 дней; связанные с неотправленными письмами
отчёты сохраняются до отправки. Очередь писем, текущий отчёт и состояние импорта
не удаляются по возрасту. Ежедневная очистка отчётов не затрагивает резервные копии
и выпуски каталога: у них отдельные правила выше.

Архивы, локальные состояния и рабочая папка outputs исключены из Docker build
context. Это не удаляет файлы на машине и не заменяет перенос необходимых
runtime-данных на сервер при развёртывании.
