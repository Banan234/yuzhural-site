# Дополнения сайта, 14 октября 2026

## Пользовательские сценарии

- `/specification/`: PDF/XLS/XLSX, до 3 файлов по 5 МиБ; описание требований, контакты и согласие. На главной и в меню есть входы. Файлы можно также приложить к КП по товарам. После успешной отправки видны имена файлов и параметры заявки. После ошибки исходные поля и вложения сохраняются.
- `/how-to-order/`: последовательность от списка до отгрузки, FAQ по наличию, отрезкам, оплате, резерву, таре, документам и вопросам к партии. FAQ JSON-LD строится из тех же данных, что видимый текст.
- `/quality/`: реквизиты и публичные документы, запрос сертификата/паспорта качества по точной марке и изготовителю. Подтверждённые материалы могут публиковаться из `data/companyEvidence.json`.
- `/services/application/`: шесть задач по реально существующим категориям; сбор исходных требований и переход к заявке с файлом либо в контактную форму.
- `/calculator/section/`: предварительный расчёт тока, выбор сечения по длительно допустимому току и падению напряжения; температурные/групповые поправки и грунт для D1; PDF/TXT, таблица проверки всех сечений, перенос параметров в заявку.
- Карточка товара: покупка выше сервисных ссылок, одна колонка до 900 px, блок партии с остатком, датой обновления файла каталога и запросом отрезков/тары/документов. Дата файла не обозначает проверку фактического остатка.
- Фильтры: восемь наиболее частых значений по числу товаров в текущей области поиска. Выбранные значения остаются доступными; полный перечень раскрывается с поиском. «Не определено»/«не применимо» скрыты, если не выбраны по URL. На экранах до 980 px панель свёрнута, товары доступны сразу.

Все новые публичные маршруты включены в router, SSR, prerender, sitemap и canonical.

## Вложения и почта

`POST /api/quote` принимает прежний JSON без файлов либо multipart с полем `payload` (JSON, до 64 КиБ) и полями `specifications` (до 3 × 5 МиБ). Пустой список товаров разрешён только при наличии проверенного вложения. Сервер проверяет расширение, сигнатуру и оглавление XLSX без распаковки XML; произвольный ZIP, макросы и зашифрованный XLSX не принимаются. XLS проверяется по сигнатуре контейнера, PDF по заголовку; полное содержимое документов сервер не анализирует. Поддержка старых XLS предполагает бинарный формат Excel, а не HTML с расширением XLS.

Multer установлен как прямая зависимость. Вложения живут в памяти запроса и передаются Nodemailer, публичные ссылки на загруженные файлы не создаются. Rate limit применяется до разбора multipart, антибот-проверка — после разбора полей. В Nginx лимит API 16 МиБ; лимиты Express и multipart сохраняют ограничения каждого маршрута. Внешний reverse proxy также должен пропускать запрос такого размера.

При `FORMS_DELIVERY_MODE=local_file` вложения сохраняются в JSON outbox в base64. Реальная SMTP-отправка по-прежнему зависит от существующей настройки форм. Конфигурация SMTP и `.env` этой работой не меняются.

## Подтверждённые условия

Резерв обсуждается индивидуально. Полная оплата переводом по счёту или наличными. Минимальный отпуск, строительные длины, стоимость/возврат тары и срок отгрузки требуют подтверждения для конкретной партии. Универсальные значения не подставляются.

### Данные о партии

`data/productSupply.json` содержит объект `items`, ключ — стабильный SKU. Запись публикуется только с корректной `verifiedAt` (ISO 8601). Допустимые поля: `minimumOrder` (в единицах товара), `reservationTerms`, `packagingTerms`, `lots` (массив `{length,count,packaging}`), `documents` (массив `{title,href}`). Если сведений нет, карточка предлагает уточнение у менеджера. Не заполняйте демонстрационными партиями. Эти данные входят в клиентскую сборку; после изменения нужна пересборка.

### Сертификаты, поставки и отзывы

`data/companyEvidence.json`: массивы `certificates`, `projects`, `reviews`. Публикуются только записи с `approved: true` после проверки материала и разрешения на публикацию. Сейчас подтверждённых материалов нет, пустые разделы на сайте скрыты.

- Сертификат: `title`, `href`, `manufacturer`, `marks`, `validUntil`.
- Поставка: `title`, `description`, `date`, `products`; необязательно `sourceHref`, `image`, `imageWidth`, `imageHeight`.
- Отзыв: `author`, `date`, `text`, `sourceHref`.

Для сертификата проверяйте номер, изготовителя, область продукции и срок действия. Фото и PDF размещайте в `public/documents/` или другом публичном каталоге сайта. Не публикуйте контактные данные покупателей или документы сделок без разрешения. Данные входят в сборку, после изменения нужна пересборка.

## Методика расчёта сечения

Источники Schneider Electric / Electrical Installation Guide (проверены 14.10.2026):

- https://www.electrical-installation.org/enwiki/General_method_for_cable_sizing — G12, G13 (температура), G14 (грунт), G16 (группы), G20 (3 нагруженные жилы, PVC 70°C).
- https://www.electrical-installation.org/enwiki/Recommended_simplified_approach_for_cable_sizing — G21 (2 нагруженные жилы, B2/C), G23 (2 жилы, D1).
- https://www.electrical-installation.org/enwiki/Calculation_of_voltage_drop_in_steady_load_conditions — G29, формулы и R/X.

Реализация и исходные табличные значения: `shared/cableSection.js`. Поддерживаются многожильный кабель, PVC 70°C, медь 1,5–120 мм², алюминий 16–120 мм², B2/C/D1, 50 Гц. Мощность — потребляемая активная электрическая. Для трёх фаз предполагается симметрия; нагружены три жилы, для одной фазы — две. Для B2 группа соприкасающаяся; для C — один слой на стене/неперфорированном лотке; для D1 — один кабель в отдельной трубе до 0,8 м в однородном грунте.

Берётся первое сечение, проходящее `Iнагрузки ≤ Iдопустимый` и, если задан номинал защиты, `Iнагрузки ≤ In ≤ Iдопустимый`, а также ограничение суммарного падения с учётом падения до линии. Это не полная координация защиты. R из источника при 90°C даёт консервативную оценку падения для PVC 70°C; X=0,08 Ω/км. КЗ, время отключения защиты, PE/N, гармоники, пуск, солнце, высыхание грунта и параллельные линии требуют отдельного расчёта проектировщиком. Результат не подтверждает соответствие выбранной марки проекту или всем нормам РФ.
