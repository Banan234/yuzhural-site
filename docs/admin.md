# Панель управления

Локальный адрес: `/admin`. Панель работает с тем же Express API и каталогом, что и сайт. Публичные ссылки на вход не добавлены. Страницы и тексты сайта редактируются в коде; редактора контента в панели нет.

## Первый вход

1. В каталоге проекта выполните `npm run admin:setup` в обычном терминале. Дважды введите собственный пароль длиной от 12 символов. Ввод скрыт; в `.env` записывается только scrypt-хеш.
2. Перезапустите процесс API. На работающем Vite фронтенд обновляется автоматически.
3. Откройте `/admin` и введите пароль. Для production нужен HTTPS и совпадающий `SITE_URL`/`ALLOWED_ORIGINS`.

Для настройки окружения без интерактивного терминала `node scripts/adminPassword.js` читает пароль из stdin и выдаёт хеш для `ADMIN_PASSWORD_HASH`. Не передавайте пароль в аргументах команды и не задавайте секрет через переменные `VITE_*`. Незаданный или неверно сформированный хеш закрывает административный API с 503. Смена хеша требует перезапуска; перезапуск завершает все сессии.

## Разделы

- **Обзор:** новые заявки, размер исходной базы и последний результат импорта.
- **Заявки:** новые обращения после подключения панели, контактные данные, состав КП, согласие и вложения. Статусы: новая, в работе, завершена, спам. Можно сохранить заметку владельца или удалить заявку вместе с вложениями. Исторические письма из SMTP и старого outbox автоматически не импортируются.
- **Товары:** поиск, постраничная выдача исходных строк прайса, изменение названия, цены, остатка и описания, скрытие с сайта. Ручные правки привязаны к стабильному ID и сохраняются после импорта. Кнопка сброса возвращает актуальные данные прайса. Новые товары добавляются в существующую категорию, единица измерения — метр; автоматическое заполнение технических характеристик для них не предусмотрено.
- **Импорт:** последний результат, очередь проверки, последние 30 записей истории. Ручной запуск импорта и загрузка прайса из панели пока не включены; используется существующий планировщик и CLI.

## Хранение и доступ

По умолчанию `data/admin/state.json` хранит товарные правки и статусы. В `data/admin/requests/` лежат заявки с вложениями. Файлы создаются с правами 0600, новые директории — 0700; обновление выполняется атомарной заменой. Нужен один API-процесс на директорию. Изменения защищены общей ревизией: при конфликте сервер возвращает 409 и не перезаписывает чужие данные. JSON-хранилище подходит для текущего небольшого объёма; для большого потока заявок и нескольких процессов потребуется БД.

Стандартный backup включает `data/admin`. Пользовательский `ADMIN_DATA_DIR` вне `data/admin` требует отдельной настройки резервного копирования. Файлы исключены из Git и Docker build context. Удаление из панели удаляет активную заявку и вложения; уже созданные резервные копии и ранее отправленные письма имеют отдельные сроки хранения. Автоматическое удаление по сроку не настроено.

Сессия: 8 часов, HttpOnly + SameSite=Strict, Secure в production. Токен сессии хранится в памяти сервера в виде хеша, пароль проверяется через scrypt. Проверяются Origin и CSRF-токен, ограничены попытки входа. Административные ответы не кэшируются. Секреты и заявки не попадают в публичный API.

Заявка сохраняется перед отправкой письма, если доступ владельца настроен. Прежние требования к включению форм и доставке остаются в силе: настройка админки сама по себе не включает `FORMS_ENABLED` и не настраивает SMTP. При ошибке сохранения форма не получает ложное подтверждение отправки.

## Публикация и ограничения статической выдачи

Nginx и prerender дополнены адресом админки и маршрутами новых ручных товаров. Для production требуется обычный выпуск обновлённого фронтенда и API; в этой задаче внешнее развёртывание не выполнялось.

Публичный API использует ручные правки сразу. После проверки наличия ручных правок браузер обновляет каталог и карточки из API при наличии ручных правок, отключая старые prerender-данные. Ответы API товаров при ручных правках получают `no-store`. Сформированные ранее HTML, JSON-LD, sitemap и скачиваемый прайс **не пересоздаются при сохранении из панели**. Для их согласования нужен штатный повторный импорт/выпуск. При ручных изменениях цен экспортный прайс пока остаётся прайсом поставщика; для полного production-цикла нужно добавить синхронизацию этих артефактов.

## Проверка

`npx vitest run lib/admin.test.js` проверяет закрытый доступ, пароль, Origin/CSRF, выход, конфликты, заявки/вложения, ручные изменения и новые товары в настоящем catalog store. Скриншоты и браузерный сценарий: `outputs/admin-2026-11-07/`. QA использует отдельную временную директорию и тестовый пароль; рабочие данные не изменяются.
