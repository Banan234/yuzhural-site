# Обновление каталога с изоляцией ошибок

Режим импорта: корректные позиции публикуются независимо от ошибок отдельных строк. Существующие карантин и предупреждения сохранены. Пустой выпуск, ошибки структуры источника, неизолированные некорректные значения и ошибки транзакции остаются блокирующими.

При неполном SSR страницы каталога runtime-импорт теперь публикует свежие данные и клиентскую страницу с noindex,follow. Страница не содержит старых цен; начальные данные включают актуальный набор товаров. Нужен работающий JavaScript. При следующем успешном SSR обычная индексируемая страница восстанавливается. Ошибки загрузки сборки/рендерера и ошибки записи не подавляются.

Диагностика неполного HTML сохраняется в data/import-diagnostics/<время-выпуска>/: исходный HTML и JSON с URL, отсутствующими товарами, наличием h1, каталогом и метаданными сборки. Диагностика сохраняется также при строгой проверке, если задан каталог. Резервный режим включён только для runtime-публикации; обычная сборка сохраняет строгую проверку.

Отчёт содержит catalogFallbacks; письмо об успешном импорте явно сообщает о предупреждении. Сетевые ошибки включают код причины Node.js, если он доступен, без вывода учётных данных.

Проверки: 52 теста в 6 файлах прошли, включая новый сценарий резервного режима: свежие данные, отсутствие старого HTML, noindex, клиентский запуск, сохранение диагностических файлов. Полный реальный импорт запущен отдельно; его результат фиксируется ниже.

## Первопричина доказана 07.11.2026

В LaunchAgent ru.yuzhural.price-import была задана EnvironmentVariables.PRERENDER_TEMPLATE_DIR=/Users/Shared/yuzhural-local-runtime/templates/review-2026-10-30. Эта настройка имеет приоритет над пустым значением в .env. Поэтому расписание использовало старый SSR, а ручной запуск — dist. Дополнительное доказательство: попытка 06.11 23:00 упала с SHA256 93d17fb66ade…, ручная 23:06 с тем же SHA256 прошла. Смена прайса не является объяснением.

Контролируемое воспроизведение на одном наборе данных, одном Node v24.22.1, одном URL /catalog/ и одинаковых параметрах: старый renderer имеет h1, но не содержит всех 28 из 28 ожидаемых ссылок; текущий dist имеет h1 и все 28 ссылок. Скрипт output/import-root-cause-2026-11-07/reproduce.mjs сохраняет обе HTML-страницы и result.json и проверяет различие программно. Тест exit 0.

Исправление: в ~/Library/LaunchAgents/ru.yuzhural.price-import.plist путь заменён на /Users/Shared/yuzhural-site/dist, задание перезагружено через launchctl bootout/bootstrap. launchctl print подтвердил новый путь в окружении загруженного задания. Интервал 00/30 минут сохранён. После исправления полный запуск по расписанию ещё не наблюдался; ручная публикация текущей сборкой подтверждена ранее. Резервный клиентский режим оставлен для будущих сбоев.
