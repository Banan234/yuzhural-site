# Адаптивные иллюстрации

Каталог/API/SSR сохраняют исходный `image` и добавляют `imageVariants` только
для выбранной иллюстрации. `ResponsiveProductImage` объявляет WebP в picture,
а исходный PNG остаётся img fallback и используется в SEO/JSON-LD. SVG и
неподготовленные изображения не меняются. Полный реестр вариантов импортируют
только сервер и генератор HTML; в браузер попадают варианты конкретных товаров.
Корзина со старым persisted payload сохраняет прежний resolver.

Готовые варианты находятся в public/responsive-images, имена содержат hash
исходных bytes и рецепта кодирования. Оригиналы не удаляются. Width320/640/960
и полный размер, без увеличения исходника; LANCZOS и lossless WebP exact.
Lossless относится к уже уменьшенному изображению; ресайз меняет детализацию.
Этот вариант согласован владельцем в T13. Цветовой профиль сохраняется,
нетипичная EXIF-ориентация требует отдельной обработки и останавливает генератор.

## Обновление иллюстраций

Это отдельная редакционная операция, **не часть импорта цен** и не серверная
обработка картинок. После изменения утверждённых PNG/реестра выполните на
временной копии проекта:

```sh
python3 -m venv /tmp/yuzhural-image-tools
/tmp/yuzhural-image-tools/bin/pip install -r scripts/responsive-images-requirements.txt
/tmp/yuzhural-image-tools/bin/python scripts/generateResponsiveImages.py --project-root /absolute/path/to/isolated-project --workers 2
```

Генератор берёт PNG из approved-записей существующего SKU-реестра и две
используемые иллюстрации главной. Он не назначает картинки товарам и не меняет
техническую достоверность обозначений. Проверяет декодированные pixels каждой
производной относительно целевого размера; повтор использует и повторно
проверяет уже созданные файлы. Метаданные активируются после успеха всех задач.

Переносить согласованным набором: public/responsive-images,
shared/responsiveImageManifest.json, shared/homeImageVariants.json и
src/styles/sections/responsive-warehouse.css. Затем форматирование CSS,
`npm run build:prod`, визуальная проверка и браузерная проверка currentSrc.
Ближайший обычный import не генерирует изображения и не меняет эти файлы.

`npm run build` автоматически запускает prebuild/checkResponsiveImages.js:
отсутствующий/не-WebP вариант или изменённый PNG со старым manifest останавливает
сборку. Проверка signature не заменяет полноценную pixel-проверку генератора.
Не удаляйте старые варианты до проверки ссылок старых HTML/возможности отката.
Публикуйте статические файлы вместе с соответствующим web-выпуском; production
наличие, MIME/cache, update/rollback проверяются отдельно от локальной приёмки.
Docker-проверка этим документом не объявляется выполненной.

Снимок T13:432 оригинала/1728 вариантов,329322008 bytes дополнительных статических
файлов. Это расход диска/контекста сборки, **не загрузка каждого посетителя**:
браузер выбирает одну подходящую производную на изображение. Полный размер
нужен для широких экранов/DPR; исходные PNG остаются для fallback и аудита.
