# Обязательный стандарт иллюстраций кабелей

Версия `approved-cable-style-1.1.0`. Дополнение геометрии утверждено пользователем 8 ноября 2026.
Предыдущая версия 1.0.0 сохранена в `assets/cable-style-reference/history/`.
Это фиксация существующего стиля, не предложение нового дизайна.

## Неизменяемые эталоны

| visualizationType   | Защищённый PNG                                     | Утверждённый исходник  |
| ------------------- | -------------------------------------------------- | ---------------------- |
| SIMPLE              | assets/cable-style-reference/simple.png            | SIMPLE v2.1            |
| MULTICORE           | assets/cable-style-reference/multicore.png         | MULTICORE v2.3         |
| LAYERED             | assets/cable-style-reference/layered.png           | LAYERED v2.1           |
| MULTICORE + LAYERED | assets/cable-style-reference/multicore-layered.png | v2.3 +75 px, вариант C |

Точные SHA-256 и пути оригиналов: `cable-image-style.json` и
`assets/cable-style-reference/standard.lock.json`. PNG скопированы без изменений.
Копии имеют режим 0444. Runtime проверяет хеш конфигурации, lock и всех четырёх
PNG до запроса. Хеш конфигурации также закреплён в исходном коде. Это защита от
случайного изменения, не от владельца файлов с правом записи/изменения кода.
Изменение стандарта требует новой версии и явного подтверждения пользователя;
нельзя автоматически пересчитывать хеши, чтобы обойти несовпадение.

## Обязательная композиция

Повторять выбранный эталон по композиции, ракурсу, направлению, масштабу,
положению, длине зачистки изоляции и металла, пропорциям, освещению, материалам,
детализации и реалистичному 3D-стилю. Никаких художественных экспериментов.
Цельная оболочка справа продолжается за правый край; разделка и выступающий
голый проводник слева полностью видны. Небольшой диагональный наклон,
компактное объёмное расположение жил, не плоский веер. Медь для медных жил,
алюминий для алюминиевых. Голый металл — продолжение жилы, не наконечник/гильза.
Прозрачный PNG без текста, логотипов, декоративных предметов, дымки и ореолов.

SIMPLE строго повторяет SIMPLE v2.1; MULTICORE — MULTICORE v2.3 с отдельной
зачисткой и утверждённой длиной голого металла. LAYERED — LAYERED v2.1 со всеми
необходимыми ступенями. Комбинированный — вариант C с его зачисткой, металлом,
слоями и левым отступом. Утверждение референса пользователем не отменяет
проверку точного количества жил у каждого нового результата.

Основной генератор проверяет композицию по альфа-каналу исходного PNG.
На последнем столбце ищется протяжённый участок, который поддерживают плотные
пиксели непосредственно внутри изображения. Проверка допускает сглаживание
и короткие разрывы, игнорирует отдельные краевые пиксели и сообщает о риске
обрезки левых концов. Если свидетельства контакта с правым краем нет, результат
остаётся NEEDS_REVIEW с предупреждением. Запрос не повторяется автоматически.
Диагональ, принадлежность края целой оболочке и видимость всех концов проверяются
вручную. Сохранённый PNG остаётся исходным.

Галерея review использует естественные пропорции PNG. При сравнении одинаковые
холсты показываются в рамках одинаковой ширины. Для холстов разной ширины
масштаб задаётся относительно общей ширины сравнения. Поля, созданные CSS,
не входят в проверку PNG. Это дополнение к существующей композиции 1.1.0.

## Разрешённые изменения конструкции

Только точное количество жил, их реальные цвета, материал и solid/stranded,
действительно необходимые слои и особенности семейства. Не копировать число
жил эталона вместо целевого профиля. Не добавлять/удалять необходимые слои.
Сечение сохраняется в metadata; по умолчанию не меняет толщину и масштаб.

Эти четыре эталона круглые. Реальные плоские изделия, СИП/скрученные пучки,
одиночные провода без общей оболочки нельзя превращать в круглый кабель ради
стандарта. Для них новый draft workflow возвращает NEEDS_REVIEW до утверждения
подходящего геометрического эталона. Недостоверный профиль также блокируется.

## Обязательная согласованность геометрии жил (добавлено в 1.1.0)

- Для 3×1,5, 4×4, 5×2,5, 7×1,5, 27×1 и любых равных сечений все
  металлические проводники имеют одинаковый визуальный диаметр с учётом только
  естественной перспективы. Нельзя случайно утолщать или уменьшать одну жилу.
- Изолированные жилы также имеют одинаковый наружный диаметр, если конструкция
  изоляции и толщина её стенки одинаковы. Равенство сечения металла само по себе
  не доказывает равную толщину изоляции разных конструкций.
- Для разных сечений круглых проводников одинаковой подтверждённой конструкции
  применяется `d₂ / d₁ = √(S₂ / S₁)`. В контракте группы нормируются к самому
  большому проводнику (`1`); например 50/95 даёт `0,725476…` (около 72,5%).
  3×240+1×120: `0,707107…`; 4×185+1×95: `0,716599…`.
- Формула задаёт относительный диаметр металла, не наружный диаметр изоляции.
  Она не используется для секторных или разных/неизвестных конструкций жил:
  такие случаи требуют отдельного подтверждения. Многопроволочная жила остаётся
  многопроволочной; проволоки внутри неё не становятся отдельными жилами.
- У каждой видимой изолированной жилы должен быть собственный голый металлический
  конец там, где эталон предусматривает разделку. Он выходит из центра изоляции,
  имеет постоянный диаметр; круглый однопроволочный конец цилиндрический.
  Цвет соответствует меди/алюминию. Запрещены утолщения, сужения, деформации,
  лишние обрубки, цилиндры, наконечники и гильзы.
- Геометрию всех жил согласовывать как единый набор; нельзя независимо заменять
  дефектную жилу элементом с другими пропорциями.
- Общий масштаб, композиция, положение, угол, зачистка, свет и четыре эталона
  остаются прежними. Физический диаметр кабеля по номинальному сечению не считается.

`deriveCableCoreGeometry(profile, input)` из `scripts/lib/cableCoreGeometry.js`
формирует контракт. Для равных сечений номинальное число не требуется для
генерации: относительный диаметр всегда 1. Для разных сечений технический вход
`sectionGroups: [{count, section, conductorShape?, conductorConstruction?}]`
должен явно описывать все группы. Количества проверяются, размеры должны быть
положительными конечными числами. Исходные номиналы сохраняются в metadata SKU;
в контракте используются только относительные диаметры. Разноразмерные группы
с неподтверждёнными ролями, цветом или исполнением по-прежнему NEEDS_REVIEW:
формула не заменяет техническое подтверждение и не разрешает их генерацию.

Расчётные проверки автоматизированы. Проверка пикселей на равенство/отношение
диаметров, число металлических концов и отсутствие артефактов не автоматизирована.
Каждый новый результат получает `geometryCheck.status = NEEDS_REVIEW` и
`pixelVerification = NOT_AUTOMATED`. Программно не утверждать геометрию по HTTP
или валидному PNG. Для ручного APPROVED обязательны отдельные флажки числа
металлических концов, равных/относительных диаметров, соосности, согласованности
геометрии и отсутствия лишних цилиндров, помимо прежних проверок.

Старые планы 1.0.0 не могут запускаться/получать APPROVED как 1.1.0 без нового
плана и review. Их файлы, исходные PNG и действующие назначения не мигрируют.
Секция диаметра не добавляется к visualKey равномерного кабеля. Для будущего
допуска разноразмерных групп относительная геометрия должна участвовать в
проверке совместимости группы; автоматически ослаблять прежний аудит запрещено.

## API и выбор референса

`prepareCableStyleRequest(root, visualProfile)` выбирает PNG строго по
`visualizationType`; неизвестный тип/NEEDS_REVIEW блокирует запрос. Модель только
`gpt-image-2.5-flare`, отдельный `IMAGE_API_KEY` codex.sale, без авторизации Codex.
Рабочий image-edit endpoint: `POST https://codex.sale/v1/images/edits`.
Multipart: `image[]` — утверждённый PNG, `model`, `prompt`, `size=1536x1024`,
`quality=high`, `output_format=png`, `background=transparent`, `n=1`.
Промпт фиксирует стиль и перечисляет целевой visualProfile.

Text-only fallback отсутствует: при неподдержанном endpoint ошибка сохраняется,
новая text-only генерация не выдаётся за редактирование. В будущем такой режим
требует явного решения, отдельной маркировки сниженной гарантии и подтверждения.
Несовпадение фактического canvas с запрошенным не является ошибкой само по себе.

## Черновики и проверки

Новый вход: `scripts/lib/cableImageStyle.js`, функция `generateCableStyleDraft`.
Только папка `outputs/`, без bindings и production manifest. Никакого
автоматического утверждения: технически исправный PNG получает NEEDS_REVIEW.

Автоматически: SHA-256 стандарта/эталонов; допустимые тип и круглая конструкция;
целое число жил и длина массива цветов; материал/solid-stranded; известность
брони/экрана; соответствие типа слоям; PNG декодирование/CRC, ненулевые размеры,
alpha и прозрачность. Сохраняются raw PNG, запрос, версия стандарта, SHA эталона,
HTTP status, фактические размеры и результаты проверки. Масштабирование,
обрезка и смещение исходного результата отключены. Повторы API отключены;
request.json создаётся эксклюзивно, повторный запуск той же папки не платит снова.

Не доказуемы текущим кодом: точное число жил на пикселях, фактический материал,
правильные цвета/слои, направление, масштаб, длина зачистки, отсутствие лишних
предметов, дымки и совпадение стиля. Проверять визуально на белом, тёмном и
шахматном фоне; сомнительные результаты оставлять NEEDS_REVIEW, ошибки FAILED.
Ручной review и отдельное применение привязок реализованы в `scripts/lib/cableStyleBatch.js`;
они требуют точного SHA PNG, актуальной версии стандарта и всех проверок геометрии.
Сам HTTP 200, PNG/alpha и решение по старой версии не утверждают новый результат.

Старые CLI live-generation/ingest/approval заблокированы, поскольку используют
старые планы и не обеспечивают этот стандарт. Старые dry-run и чтение статуса
сохранены. Не возобновлять исторический production-run и не менять его manifest.

## Разделение стиля и конструкции — construction-contract-1

Эталон задаёт только внешний визуальный стандарт; его броня, экран, число жил
и внутренние слои не являются техническими данными целевого изделия.
`cableTechnicalProfile.js` формирует отдельный проверяемый контракт до API:
перечень жил с взаимно однозначным соответствием металлическим концам,
материал/исполнение, явные роли и область каждого слоя, отдельный дренаж экрана.
Слюдяной огнестойкий барьер вокруг проводника под индивидуальной изоляцией
не является общей металлической бронёй. Экран из тонкой фольги с дренажом
не изображать стальными бронелентами. Неизвестные/противоречивые слои блокируют
запрос. Неуказанные наполнители не превращать в придуманные видимые ступени.
Разрешено полностью перестраивать внутреннюю геометрию под целевой профиль,
сохраняя утверждённые масштаб, композицию и параметры визуального стиля.
Контракт и результаты проверки числа жил/концов/слоёв сохраняются в metadata.
Пиксельная проверка пока ручная, обязательная: до неё NEEDS_REVIEW, даже при HTTP200.
Изменение контракта меняет prompt/cache key; старый план не оплачивается повторно
и не используется для нового запроса без обновлённого dry-run.
Стандарт 1.1.0 и четыре эталонных PNG не изменяются.

## Техническое дополнение construction-contract-2: FRLS, экран, броня

Обязательны независимые параметры `fireBarrier`, `fireBarrierMaterial`,
`fireBarrierPlacement`, `screen`/`screenType`, `armor`/`armorType`.
Они сохраняются в техническом контракте запроса; LAYERED остаётся только типом
визуализации и не заменяет параметры конструкции.

Подтверждённые правила и ссылки производителя — `data/cableTechnicalConstructionRules.json`.
ВВГнг(А)-FRLS и КВВГЭнг(А)-FRLS: металл → тонкая обмотка слюдосодержащими
лентами → цветная изоляция. На каждой разделанной жиле показывать короткий
видимый участок слюдяной обмотки между металлом и изоляцией, а не только
светлое плоское кольцо торца. Сохранять общий масштаб и длину разделки эталона.
Другие FRLS без подтверждения материала и положения барьера — NEEDS_REVIEW;
наличие букв FRLS не разрешает придумывать слои.

Экран может быть медной проволочной оплёткой, медной лентой/фольгой,
алюминиевой фольгой или алюмофлексом. Выбирать только исполнение из документации
производителя с сохранением источника. Для текущего КВВГЭнг(А)-FRLS выбран
документированный Камкабелем экран из тонкой медной ленты без выдуманного
дренажа. Это вариант каталожной иллюстрации; не утверждение производителя SKU.
Экран — тонкий слой; броня изображается исключительно при armor=true.
Внутренняя полимерная оболочка, слюдяной барьер, экран и броня имеют разные роли.
Новые PNG — NEEDS_REVIEW до отдельной проверки жил, концов и всех слоёв.
Защищённые PNG и визуальная конфигурация approved-cable-style-1.1.0 неизменны.

### Обязательное различие экрана и брони

Экран обеспечивает электромагнитное экранирование; броня — механическую защиту.
Для КВВГЭнг(А)-FRLS подтверждена медная фольга/лента (Подольсккабель, раздел
«Конструкция»). В новом контрольном варианте выбрана тонкая медная фольга:
гибкая кромка с ничтожной видимой толщиной, мелкие естественные складки и
небольшое раскрытие края; не гладкий жёсткий цилиндр, не массивная гильза и
не поднятый диагональный шов брони. Плетёную сетку изображать только при
подтверждённой проволочной оплётке, с видимым перекрещиванием тонких проволок.
Эталон LAYERED не разрешает добавлять ни экран, ни броню. Принятый контрольный
ВВГнг(А)-FRLS 3×2,5 сохраняется; его конструкция не переносится на другие марки
без отдельного подтверждения. Новые результаты остаются NEEDS_REVIEW.

## Универсальный условный экран — universal-screen-1.0.0

Утверждён пользователем для ВСЕХ экранированных кабелей каталога. Этот раздел
заменяет прежние требования выбирать отдельное визуальное исполнение экрана
по марке/материалу производителя; требования подтверждать наличие экрана,
брони, жил и огнестойкого барьера сохраняются.

Постоянная конфигурация: `data/cableScreenVisualStandard.json`. Один тонкий,
гибкий серебристо-металлический слой совмещает непрерывность фольги и мелкую
хорошо различимую перекрёстную сетчатую текстуру. Не крупная сетка, не массивный
металл. Без толстых спиральных лент, широких полос и выраженных броневых швов.
Экран охватывает внутреннюю конструкцию под наружной защитой. При наличии
брони показывать ДВА отдельных слоя: экран внутри и механическую броню снаружи.

Это условный визуальный стандарт, не заявление о фактическом материале или
исполнении экрана производителя. Реальный screenType/source сохраняется в
metadata отдельно от screenVisualStandard/screenRendering/materialClaim=false.
Неизвестный реальный материал экрана не блокирует условную иллюстрацию при
подтверждённом наличии экрана; отсутствие подтверждения наличия блокирует API.
Не добавлять экран в неэкранированный кабель. Данные жил, их число, цвета,
металл и огнестойкие барьеры не менять. Четыре эталона и визуальная конфигурация
1.1.0 сохранены, масштаб/композиция/наклон не меняются. Новый prompt меняет
cache key; массовая генерация и автоматическое применение не разрешены.

## Постоянный реестр утверждений

`data/cable-approved-results/registry.json` индексирует APPROVED по visualKey,
а не по изменяемому тексту промпта. В той же папке хранятся отдельные неизменённые
PNG, исходный request, group и решение пользователя. Перед reuse проверяются
SHA-256 PNG, профиль, версия стандарта/эталона и экранный стандарт. Планировщик,
исполнитель партии и прямой generateCableStyleDraft обращаются к этому реестру.
Удаление временного outputs-кэша и изменение промпта не инициируют повторную
оплату уже утверждённой конструкции. Повреждение/несовместимость утверждённого
результата блокирует работу вместо автоматической перегенерации.
Для будущей публикации prepareApprovedBindingPatch может принять актуальную
currentGroup с тем же visualKey и профилем: обновление состава SKU не меняет
утверждённый PNG. Проверки актуальных productHash, bindings и защиты ручных фото
сохраняются. Подготовка patch не публикует файлы и не меняет bindings/manifest.
Проверка SHA эталонного PNG повторяется адаптером непосредственно перед upload;
в защищённом pipeline отсутствие референса не допускает text-only fallback.

## Удлинение разделки MULTICORE — multicore-stripping-1.0.0

Постоянное перспективное дополнение: `data/cableMulticoreVisualRules.json`.
Для MULTICORE и MULTICORE + LAYERED видимая длина ИЗОЛИРОВАННЫХ жил между
срезом общей оболочки и оголённым металлом увеличивается на 20–25%.
Длина голого металла, диаметры/число/цвета жил, стенка оболочки, общий масштаб,
камера, наклон, направление и композиция остаются прежними. Компактный объёмный
пучок без неестественного растяжения. Для многослойных кабелей нельзя сокращать
видимые ступени брони, экрана, внутренних оболочек и барьеров; при известном
конструктивном конфликте — NEEDS_REVIEW. SIMPLE и чистый LAYERED без изменений.
`cableImageStyle.js` включает правило автоматически по visualizationType и
сохраняет его в request/review metadata. Это явно разрешённое исключение из
прежнего требования буквально повторять длину разделки изолированных жил эталона.
Четыре исходных PNG, базовая визуальная конфигурация 1.1.0, все APPROVED и их
привязки сохраняются. Новое правило не является поводом перегенерировать APPROVED.
Процент в пикселях и соблюдение масштаба требуют ручной проверки.

## Явно разрешённые контроли новых геометрий

`new-geometry-control-1.0.0` — ограниченный режим prepareGeometryPilot для трёх
SKU: ПуГВ YU-0005011, ШВВП YU-0005219, СИП-4 YU-0004818. Перед API профиль
повторно сверяется с текущим каталогом и familyVisualRules; любые расхождения
или критическая неоднозначность блокируют запрос. SIMPLE PNG используется
только для стиля, а не как конструкция круглого кабеля. Новые геометрии пока
не считаются APPROVED и не разрешают массовый запуск. Общая оболочка в контракте
существует только при hasOuterJacket=true. Несколько проволок внутри одной жилы
не увеличивают число изолированных жил. Все результаты NEEDS_REVIEW.
Пиксельные семантические проверки не объявлять автоматическими PASS: программно
проверяются входной контракт, PNG/alpha/размеры/границы; материал/число жил/слои
и стиль дополнительно требуют визуальной проверки. Не менять bindings.

## Геометрия общей оболочки — outerSheathGeometry

Обязательный технический параметр: FLAT, ROUND, NO_COMMON_SHEATH; UNKNOWN
блокирует генерацию и подбор до NEEDS_TECHNICAL_REVIEW. Значение выводится из
подтверждённых geometry/hasOuterJacket, не из числа жил или слова в названии.
Две жилы не означают плоский кабель. FLAT и ROUND имеют разные visualKey уже
через существующие geometry/hasOuterJacket; новый параметр избыточен к ним и
не сбрасывает принятые ключи. Конфликт явно заданного параметра блокируется.
Каноническая геометрия проверяется при создании identity, технического контракта
и повторном использовании APPROVED; прочие critical-поля профиля сохраняются.
Утверждённые геометрические контроли отдельно хранятся в
`data/cable-geometry-references.json` с SHA/ссылкой на постоянный реестр.
ПуГВ — утверждённый одиночный многопроволочный белый медный провод без общей
оболочки. При нормальном планировании подходящие SKU с тем же visualKey/профилем
переиспользуют этот APPROVED, без перегенерации. Цвета/семейства не расширять
только по сходству названия. Четыре исходных стилевых PNG не заменяются.
ШВВП и СИП-4 пока только контрольные NEEDS_REVISION/NEEDS_REVIEW, не production.

## Уточнение будущей композиции общей оболочки

`common-sheath-stripping-composition-1.0.0` из
`data/cableStrippingCompositionRules.json` подключено к реальным промптам.
Для новых изображений с подтверждённой общей оболочкой и несколькими жилами,
где это конструктивно и визуально уместно, видимую длину изолированных жил
увеличивать примерно на 20–30% относительно выбранного текущего APPROVED.
Длину оголённого металла, общий масштаб, направление и наклон сохранять.
Не создавать скученность, пересечения или лишние изгибы; не сокращать видимость
реальных слоёв. Не применять механически к одиночным/безоболочечным конструкциям.
При конфликте сохранить безопасную геометрию и оставить ручную проверку.
Уточнение заменяет диапазон старого multicore-правила для подходящего нового
запроса, а не умножается на него. Явные исторические targeted edits сохраняют

## Архив и референсы новых запросов

Архивные PNG первой массовой партии служат материалом для ручного выбора.
READY_FOR_MANUAL_REVIEW не даёт права передавать PNG в API как стилевой образец.
Подбор дополнительного референса в основном prepareCableStyleRequest использует
только постоянный реестр с ручным APPROVED и совпавшим SHA PNG/решения/visualKey.
cableReferenceCompatibility проверяет геометрию, наличие общей оболочки,
материал и исполнение проводника, экран, броню и огнестойкий барьер.
Одножильные референсы разрешены только для одножильных конструкций.
Защищённые четыре исходных эталона продолжают задавать базовый стиль 1.1.0.
Архивные PNG и сохранённые черновики не добавляются в библиотеку автоматически.

## Независимые разрешения каталога и референсов

APPROVED_FOR_CATALOG разрешает назначение PNG в каталоге.
APPROVED_AS_REFERENCE отдельно разрешает дополнительный стилевой референс.
Новое ручное утверждение по умолчанию записывает APPROVED_FOR_CATALOG=true
и APPROVED_AS_REFERENCE=false. Только явное разрешение референса даёт true.
Подбор проверяет этот флаг в постоянном реестре и в решении approval.json,
затем SHA, происхождение в постоянном архиве и совместимость конструкции.
Отсутствующий флаг трактуется как отсутствие разрешения референса.
Ранее отдельно разрешённая библиотека из 21 результатов сохраняет разрешение.
Пять архивных результатов и новые утверждения архива разрешены только для сайта.
Четыре защищённых исходных PNG продолжают задавать стиль 1.1.0.

## Допуск изображений в каталог

[Правила чистого каталога](docs/catalog-image-policy.md) действуют для API,
импорта, публикации привязок, пересборки и восстановления выпусков.
Разрешение для генераций берётся из постоянного реестра. Старый mapping
и архивный PNG сами по себе не дают права показа. При отсутствии утверждённой
совместимой генерации, фотографии или ручного назначения используется штатная
заглушка. Показ в каталоге и использование как референса разрешаются отдельно.

## Композиция многожильной разделки

`data/cableMulticoreCompositionRules.json` подключён к промптам новых MULTICORE
и MULTICORE + LAYERED. Силуэт уравновешивается по вертикали, ось группы жил
совпадает с проекцией оси оболочки. Компактная раскладка в глубину следует
реальному сечению, без диагональной лестницы, плоского веера или одного ряда.
У четырёх равных круглых жил ориентир — две смещённые пары. У каждой жилы
сохраняются соосность, полная видимость медного среза и сопоставимая длина
оголённого металла вдоль её оси. Оставляйте справа продолжение целой оболочки.
Ширина 80–90% — ориентир при сохранении целых концов и компактного пучка.
Проверки в решении по новым черновикам обязательны. Ранее утверждённые
иллюстрации, четыре защищённых эталона, версия стандарта и SHA остаются прежними.

Защищённый PNG передаётся как первый multipart `image[]`. Для новой
многожильной композиции требуется второй PNG с ролью геометрии и
`APPROVED_AS_REFERENCE=true` в реестре и решении. Эталон другого числа жил,
укладки, оболочек, слоёв или типа композиции не даёт допуск к API.
Технический контракт имеет приоритет над визуальной анатомией обоих входов.

При приёмке новых черновиков силуэт проверяется по альфа-каналу. Для четырёх
равных круглых жил поперечный разлёт и смещение центра измеряются относительно
диаметра видимой оболочки. Признак лестницы учитывает порядок концов вдоль
оси и поперёк неё. Числовые границы являются контролем этой конкретной
геометрии и не задают универсальную раскладку для других конструкций.
Состав жил и слоёв сверяется с наблюдениями по тому же SHA PNG.
