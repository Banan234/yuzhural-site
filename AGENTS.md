# Правила проекта

## Иллюстрации кабелей

Перед любой работой с генерацией, промптами, обработкой, проверкой и привязкой
изображений кабелей обязательно прочитать `CABLE_IMAGE_STYLE.md` и соблюдать
`cable-image-style.json`. Использовать четыре защищённых эталона из
`assets/cable-style-reference/`; проверять SHA-256 через `loadCableImageStyle`.
Не менять модель, эталоны, стиль и контрольные суммы без явного согласования
пользователем новой версии. Не обходить блокировку старых live-generation CLI.
Генерация только по явному заданию; стандартный новый результат — NEEDS_REVIEW,
без автоматической production-привязки. Не запускать массовую генерацию или
публикацию, если пользователь поручил только dry-run/стандартизацию.

## Геометрия токопроводящих жил — approved-cable-style-1.1.0

Обязательны равные визуальные диаметры при одинаковых сечениях и одинаковые
наружные диаметры изоляции при одинаковой её конструкции/стенке. Для разных
сечений круглых проводников одинаковой конструкции использовать отношение
диаметров sqrt(S2/S1), сохраняя общий масштаб эталона. Не применять эту формулу
к секторным/неизвестным конструкциям и не выводить из неё наружный диаметр изоляции.
Каждая видимая жила имеет собственный центрированный металлический конец;
никаких случайных утолщений, сужений, деформаций или дополнительных цилиндров.
Геометрию корректировать согласованно у всех жил, а не патчем одной серой жилы.
Геометрический контракт и расчёты — `scripts/lib/cableCoreGeometry.js`.
HTTP 200/PNG не доказывают геометрию: NEEDS_REVIEW до обязательных ручных проверок.
Не менять четыре эталонных PNG, композицию, масштаб, наклон, модель и /images/edits.
Старые планы/утверждения 1.0.0 не выдавать за проверку по 1.1.0.

Эталон — только стиль, не техническая конструкция. Перед /images/edits обязателен
отдельный construction-contract из cableTechnicalProfile.js: взаимно однозначные
жилы/концы, роли слоёв, отдельный дренаж. Не копировать броню эталона в кабель
без брони; не путать фольговый экран и слюдяной барьер со стальными лентами.
Неизвестная конструкция блокирует запрос. Проверка пикселей вручную обязательна.

FRLS/экраны: обязательно применять cableTechnicalConstructionRules.json.
Независимо фиксировать fireBarrier/Material/Placement, screen/Type, armor/Type.
Слюдяную обмотку под индивидуальной изоляцией показывать видимой ступенью.
Другие FRLS без документации барьера — NEEDS_REVIEW до API.
Вид экрана всегда условный universal-screen-1.0.0 из cableScreenVisualStandard.json;
подтверждённое наличие экрана обязательно, его реальный материал хранить отдельно.
Экран = electromagnetic-screening, броня = mechanical-protection. Не использовать
броню как универсальный шаблон экрана. Для любого экрана — один тонкий гибкий
серебристый сетчато-фольгированный слой с мелкими перекрещивающимися линиями.
Это условная иллюстрация, не утверждение материала производителя. Броня остаётся
отдельной механической защитой, только при armor=true. Старые правила выбора
внешнего вида по фактическому материалу экрана заменены этим правилом.
APPROVED хранить через cableApprovedResults.js в data/cable-approved-results/,
проверять реестр до каждого нового платного запроса. Не терять утверждения при
смене prompt/cache key или очистке outputs. Несовместимость — блокировка,
а не повторная генерация. Проверять точный SHA PNG референса перед upload.
Для новых MULTICORE, включая MULTICORE + LAYERED, автоматически применять
multicore-stripping-1.0.0 из cableMulticoreVisualRules.json: только видимая длина
изолированных жил +20–25%, без удлинения металла, без изменения масштаба/слоёв.
SIMPLE/чистый LAYERED и прежние APPROVED не менять и не перегенерировать.
Геометрия общей оболочки: deriveOuterSheathGeometry задаёт FLAT/ROUND/
NO_COMMON_SHEATH по подтверждённому профилю; UNKNOWN/конфликты требуют
NEEDS_TECHNICAL_REVIEW. Не определять форму по числу жил. FLAT/ROUND не смешивать
при visualKey/reuse/будущем подборе SKU. Существующие ключи сохраняются.
Отдельные утверждённые геометрические эталоны — cable-geometry-references.json;
не заменять ими четыре исходных стилевых PNG и не менять bindings без команды.

## Уточнение будущей композиции общей оболочки

`common-sheath-stripping-composition-1.0.0` из
`data/cableStrippingCompositionRules.json` подключено к реальным промптам.
Для новых изображений с подтверждённой общей оболочкой и несколькими жилами,
где это конструктивно и визуально уместно, видимую длину изолированных жил
увеличивать примерно на 20–30% относительно выбранного текущего APPROVED.
Длину оголённого металла, общий масштаб, направление и наклон сохранять.
Не создавать скученность, пересечения или лишние изгибы; не сокращать видимость
реальных слоёв. Не применять механически к одиночным/безоболочечным конструкциям.
При конфликте сохранить безопасную геометрию и оставить ручную проверку.
Уточнение заменяет диапазон старого multicore-правила для подходящего нового
запроса, а не умножается на него. Явные исторические targeted edits сохраняют
собственные ограничения. Ранее APPROVED, их PNG, статусы и привязки не менять
и не перегенерировать из-за этого пожелания. Основной стиль 1.1.0 и четыре
защищённых PNG остаются прежними.

### Прилегание слоёв — layer-contact-1.0.0

Правило `data/cableLayerContactRules.json` подключено к запросам через
`cableLayerContact.js`. На подтверждённом интерфейсе непосредственного контакта
не изображать воздушное кольцо или свободную трубку: оболочка плотно охватывает
изоляцию, границы реальных слоёв остаются видны. Для текущих одножильных
КГВВнг(А)-LS и ВВГнг(А)-LS это явное пользовательское требование. Не распространять
вывод на другие конструкции только по количеству жил. Документированные
заполнители, разделители, специальные слои и предусмотренные полости сохранять.
Неизвестное прилегание не считать подтверждённым. Проверка пикселей вручную;
до неё NEEDS_REVIEW. Уже APPROVED PNG и привязки не менять из-за правила.
